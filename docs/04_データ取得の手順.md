# データ取得の手順

`reference/` にあるスクリプトは前身プロジェクトで実際に動いたもの。
インポートパスを直せばそのまま使える。

## 全体の流れ

```bash
# 1. 製品ページのレビュー（ページ送りあり）
node --experimental-strip-types scripts/fetch-reviews.mjs earbuds

# 2. 店舗のレビュー（深さを足す）
node --experimental-strip-types scripts/fetch-shop-reviews.mjs earbuds

# 3. 観点を数える（1ページ30件ごとに Gemini）
node --experimental-strip-types scripts/extract-aspects.mjs earbuds
```

所要時間の実測：1が約8分（130リクエスト）、2が約15分（296リクエスト）、3が約4分（114回の呼び出し）。

## クロールの作法（`reference/maker-crawl.ts`）

`MakerCrawler` が面倒を見る。**自前で `fetch` を書かないこと。**

- `robots.txt` を読んで従う
- ホストごとに3秒間隔
- 1回の実行あたりのリクエスト上限
- ETag / Last-Modified でのキャッシュ

**403 が返ってきたら、そこで止める。** ブラウザを装って回避しない。

## 本文の置き場所（`reference/page-text.mjs`）

**取得したページ本文はリポジトリに入れない。** `.cache/page-text/<ジャンル>/<出典>/<商品ID>-p<N>.txt` に置き、
`.gitignore` に入れる。

読むために取得することと、他社が書いた文章をリポジトリに入れて再配布することは別の行為。
リポジトリに残すのは、抽出した件数・引用・商品の識別子だけ。

**パスに出典を含めること。** `reviews` と `shop-reviews` を同じ場所に置くと、
後に走ったほうが先の本文を黙って上書きする。

## 再抽出だけしたいとき

`--from-cache` を付けると、取得済みのページから抽出だけをやり直す。

```bash
node --experimental-strip-types scripts/fetch-reviews.mjs earbuds --from-cache
```

クローラはキャッシュヒットでも毎回再検証するため、これが無いと正規表現を1つ直すたびに
相手のサーバへ100リクエストを送ることになる。

## 抽出の要点（`reference/extract-aspects.mjs`）

1. **1ページ30件ごとに1回呼ぶ。** 件数は加算できる
2. **モデルは Flash Lite に固定。** 共有の環境変数から継承しない（枠切れで静かに空になる）
3. **引用を原文と照合し、通らなければ件数ごと捨てる**
4. プロンプトで明示すること：
   - レビューは区切り文字（` / `）で区切られていること（件数を数えるため）
   - 否定表現（「〜ない」「〜しにくい」「期待したほどでは」）を見落とさないこと
   - 商品説明やショップの宣伝文は購入者の声ではないので数えないこと

## 環境変数

```
GEMINI_API_KEY=            # 必須
RAKUTEN_APPLICATION_ID=    # あるとカバレッジが上がる（出品の列挙に使う）
RAKUTEN_ACCESS_KEY=
RAKUTEN_AFFILIATE_ID=
AMAZON_ASSOCIATE_TAG=      # 審査通過後。★と件数のみ
```

**資格情報が無い機能は、エラーにも空欄にもせず、画面から黙って消すこと。**

## 同梱データ

`data/genre-aspects.json` と `data/genre-products.json` は、前身プロジェクトで実際に取得・抽出した
本物のデータ。**クロールと Gemini 呼び出しをせずに画面を作り始められる。**

- `genre-products.json`：完全ワイヤレスイヤホン97商品（名前・価格・画像・型番・仕様・レビュー数）
- `genre-aspects.json`：24商品ぶんの観点集計（のべ1,780レビュー・151観点・引用つき）
