## 2. 混ぜ方

**C の骨組みを、B の見た目で、A の「似ているもの」と一緒に。**

| 出どころ | 使う | 使わない（理由） |
|---|---|---|
| 案A | これに似たもの（押した商品を真ん中に）・くらべる（違うところから先に） | すべての点の色のリング（色が多い）・文字の箱の四象限（嫌い1・4） |
| 別案B | 白地・モノが主役・色は声の2色だけ・商品の絵の丸と点線・浮いた丸いタブ・空きタイル | 下の輪（チップのほうが誰でも分かる）・半円のゲージ（分母が見えない） |
| 別案C | 声札・声の3つの型・わたしの条件・読めた深さ・観点の辞書と承認 | 紙色の地（B の白に合わせる）・「段」「声札」などの言葉を画面に出すこと |

## 3. 価格.com・マイベストとの違い（体験）

| | 価格.com 型 | マイベスト 型 | この案 |
|---|---|---|---|
| 最初に目に入るもの | 仕様と値段の表 | 1位の商品 | 商品の絵が、声の線に並ぶ |
| 答える問い | どの仕様か・どこが安いか | どれがいちばんか | 買った人はどう感じたか。自分と同じ人は |
| だれの判断か | メーカーの仕様と値段 | 編集部の検証 | 買った人全員の件数（AI が分類） |
| 読めていない商品 | 見せ方の決まりは無い | 載らない | 「これから読みます」と見せる |

2つのサイトにもレビューや口コミはある。比べたのは「主に見せるもの」。

## 4. だれでも分かるための約束

- 画面の言葉は日常語：観点 → **気になること**、分離度が低い → **みんな同じ／みんな満足**、言及なし → **ふれていない**、段0 → **これから読みます**、条件 → **わたしと同じ人だけ**。「声札」「段」「収縮」は画面に出さない（中だけで使う）
- 1画面1問い：見出しを質問にする（「どこが気になりますか？」「サイズは合いますか？」）
- はじめての説明は1回だけ、3行
- 色だけに頼らない（左右の位置と「不満」「満足」の言葉を添える）。好み（サイズ・味）には赤も青も使わない
- 数字は必ず分母つき。押せるものは44px以上、文字は11px以上
- 一覧（カード）には順位を付けない。並びは「読めたレビューの多い順（順位ではありません）」

## 7. AI の費用（有料を使う前に聞くための数字）

料金は第三者の料金表（2026-09）の値で、**公式の確認はまだ**。トークン数は推定。

| | 入力 | 出力 |
|---|---|---|
| トークン（10カテゴリを1回） | 840万〜1,080万 | 360万〜580万 |
| 単価（Gemini 3.1 Flash-Lite・100万あたり） | $0.25 | $1.50 |

- 合計 **$7.5〜11 / 1回**（約1,100〜1,700円。1ドル150円で換算）。まとめて送る方式（バッチ）なら半額。やり直しを含めても上限 $30 程度の見込み

- 無料枠は、送った内容が Google の改善に使われることがある（料金表の注記）。送るのは公開されたレビューだけ
- **無料枠でも回るので、有料枠は「急ぐとき」だけ。** 使う前にこの表で改めて聞く

## 9. 実装の進め方

1. **データの形を広げる**：3つの声の型・わたしの条件・数えないもの。判断は純粋関数に集めてテストで固定（キーなしでできる）
2. **画面を作る**：ホーム・カテゴリ（線／一覧）・商品・これに似たもの・くらべる・わたし・さがす。イヤホンの実データで（キーなしでできる）
3. 3つで抽出し直す → ゲートの値を決める（`GEMINI_API_KEY` が要る）
4. 10へ広げる（無料枠で約5日。急ぐなら有料・聞いてから）
5. 公開の準備：検索に出すページを決める（今は全部 noindex）・Amazon の審査

作り方は今の Vite ＋ TypeScript のまま（フレームワークを足さない）。アプリ化は、まずホーム画面に置ける形（PWA）から。
