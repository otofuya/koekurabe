# 体験設計：「★の中身」を実装する前に考えたこと

作成日：2026-09-25。前提：[11](11_新しい案_星の中身.md)（オーナーがコンセプトを了承）

オーナーの依頼：「ユーザーの体験を深く推論分析し、安直に考えずになるべく使いやすく新鮮味のあるUIUXとして実装を進めて」

## 1. 人は、どこから来るか

試作はホームから始まるが、実際の入口はほとんどが**商品ページ**になる。

| 入口 | 来た人が知っていること | だから |
|---|---|---|
| 「WF-C710N 口コミ」で検索 | 商品名だけ。このサイトは知らない | 商品ページが単独で意味を持つ。説明なしで3秒で分かる |
| 家族から送られた「くらべる」の URL | 2つの商品名だけ | くらべるページも単独で読める。1行目に結論 |
| 楽天の商品ページの URL を貼る | 自分が見ていた商品 | 検索窓は URL を受け付ける |
| ホーム | 何も | 例（本物の商品）を見せて、形を覚えてもらう |

**結論：ホームを作り込むより、商品ページを「着地したその画面で完結する」ように作る。**

## 2. 商品ページの最初の1画面（390×約700）に入れるもの

買う直前の人は、読むのではなく**探して**いる。探しているのは「自分にとってのダメな理由があるか」。

1. どの商品か：本物の商品画像・名前・値段
2. ★と、その中身：★4.31 → よかった 3つ｜残念だった 3つ、何件中何件
3. 次にできること：行を押すと、ひとことと乗り換え先

それ以外（全部の項目・仕様・数え方）は下へ。**評判が先、仕様が後**（設計原則4）。

### ★が「開く」形

★の札と、その中身を**1枚のカードにする**。上の段に ★4.31、下の段が左右に割れて「よかった｜残念だった」。
★を見慣れた人ほど「この★の中身」と読める。読み込み時に、下の段が中央から左右へ開く（動きを減らす設定の人には動かさない）。

### 左はいつも「よかった」、右はいつも「残念だった」

試作では、観点の画面だけ残念が左だった。**画面ごとに左右が変わると、数字を読む前に迷う。** すべての画面で左＝よかった（青）、右＝残念だった（赤）に固定する。くらべる画面でも、各商品の中で同じ順。

## 3. 数字の読まれ方

- 「14」だけでは尺度が無い。**カードの見出しに「129件中」**、行の下に129件を全長とする細い帯
- 同じ観点が「よかった」と「残念だった」の両方に出ることがある（ノイキャン 32｜11）。丸めない（設計原則5）。**両方に出ること自体が「合う人と合わない人がいる」という情報**
- よかった＋残念 ≠ ふれた人数。1件のレビューが両方に数えられることがあるので（02 第5節）、「ふれていない＝129−21−14」とは書かない。帯はそれぞれ129件を全長にして別々に描く
- 「3人」ではなく「3件のレビュー」（設計原則4）

## 4. 1つの心配を確かめる：下から出る板

行を押すと、商品ページの上に**下から板が出る**（ページを移らない）。

- 今見ている商品が後ろに残るので、「この商品の、この心配」を見ている感覚が途切れない
- 親指の届く位置で閉じられる（下に引く・×・戻る）。URL に `?k=fit` が付き、戻るボタンで閉じ、その URL を送れる
- 板の中身：よかった／残念だった の件数（同じ129件を全長にした帯）→ 買った人のひとこと（原文・出典つき）→ **その残念がもっと少ない、同じくらいの値段の商品**
- PC では右側に出す

### ひとことの向き

今のデータの引用には、よかった・残念の向きが無い（11 第3節）。**向きを推測して左右に振り分けない。** 板の中で「よかった・残念どちらも」と書いて、そのまま3件出す。向きは抽出で持たせるまで待つ。

## 5. 乗り換え：心配を持ったまま、次の商品へ

乗り換え先を押すと、その商品のページが**同じ心配の板を開いた状態で**出る。
つけ心地を気にして乗り換えた人は、次の商品でもまずつけ心地を見たい。毎回探し直させない。

- 乗り換え先の条件は 11 第6節（値段0.6〜1.4倍・30件以上・ふれた声3件以上・3分の1以上少ない）
- 見つからないときは理由を書く（「同じくらいの値段で、はっきり少ない商品は見つかりませんでした」）
- 読めたレビューが30件未満の商品では、乗り換え先を出さない（割合がぶれるため）。そう書く

## 6. 気になることを覚える（新しいところ）

1つの商品で「つけ心地が気になる」と分かった人は、**次の商品でも同じことを知りたい。**

- 板の中に「気になる」の印。押すと、この端末に覚える（登録なし。オーナーの回答3）
- 覚えた観点は、どの商品ページでも中身カードの上に**先に**出る：「あなたが気にしていること：つけ心地 よかった21｜残念14」
- くらべる画面でも先頭に、カテゴリの並びの最初の選択にも使う
- はじめて印を付けたときだけ「ほかの商品でも、つけ心地を先に見せます」と出す

楽天のレビュー要約は「その商品についての文章」。ここは「**あなたの質問に、どの商品でも同じ場所で答える**」。ここが一番の違いになる。

## 7. くらべる

- 入口は3つ：乗り換え先の「くらべる」、商品ページの「くらべるに入れる」、送られてきた URL
- 「くらべるに入れる」は2つまで。画面の下に小さな札（2つの画像と「くらべる」）が浮く。1つのときは「もう1つ選んでください」
- 1行目は件数から作る定型文（AI に書かせない。設計原則5）：「★は A が上（4.31・4.06）。でも つけ心地 の残念は B が少ない（60件中1件・129件中14件）」
- 並び：気にしていること → ちがいが大きいこと → 同じくらい → 片方だけ声があること
- 仕様は最後。推定の値には「推定」（設計原則4）

## 8. カテゴリ

- 「何が気になる？」は、散らばりのゲートを通った観点だけ押せる（設計原則7）。通らないものは押せない形で理由を出す（「音質：どれも好評で差が出ません」）
- 押すと並びが**動く**（どの商品がどこへ行ったか目で追える）。並びは「残念が少ない順」で、順位ではないと書く
- ふれた声が3件未満の商品は、最下位ではなく**別の段**（設計原則10）
- まだ読んでいない商品も**名前を出す**（設計原則2）。たたんでおく
- 予算で絞ると、外れた商品は**消さずに薄くする**（設計原則14）

## 9. 見た目の約束

- 白地。色は よかった（青）・残念だった（赤）の2つだけ。★は黒（楽天の黄色を借りない）
- 数字は Outfit、文字は Zen Kaku Gothic New。数字は大きく、説明は小さく（好き10・11）
- 商品画像が主役（設計原則15）
- 押せるものは44px以上、文字は11px以上。色だけに頼らず「よかった」「残念だった」の言葉を必ず添える
- 動きは意味のあるところだけ：★が開く・板が出る・並びが動く。動きを減らす設定では止める

## 10. 作り方

- Vite ＋ TypeScript のまま。フレームワークは足さない
- 判断はすべて `lib/nakami-model.ts` の純粋関数にしてテストで固定する（中身・乗り換え・並び・くらべる・定型文・検索の解釈・表示名）
- 画面は小さな DOM の部品で組み、ページを移るときは履歴 API で書き換える（戻るボタンがそのまま効く）。対応するブラウザでは画面の切り替えを滑らかにする（View Transitions）
- 覚えること（気になる・最近見た・くらべる）は localStorage。使えない環境では覚えないだけで、画面は壊れない
- 古い画面（四象限・観点ランキング・旧くらべる）は外す。URL は新しい画面へつなぐ（`/aspect/earbuds/fit` → カテゴリの「つけ心地」）

## 11. 実装した結果（2026-09-25）

### 画面と URL

| URL | 画面 |
|---|---|
| `/` | ホーム：見出し・さがす・「たとえば」（いちばん多く読めた商品の中身）・最近見た・気にしていること・カテゴリ・使い方 |
| `/reviews/:id`（`?k=観点` で板が開く） | 商品：★が開くカード・気にしていること・ぜんぶの項目・仕様・楽天で見る |
| `/compare/:カテゴリ`（`?k=`・`?max=`） | カテゴリ：何が気になる？・予算（薄くする）・残念が少ない順・ふれた声が少ない段・まだ読んでいない商品 |
| `/vs/:a/:b`（`?k=`） | くらべる：定型文の1行目・いま見ている／気にしていること・ちがいが大きい・同じくらい・片方だけ・仕様 |
| `/aspect/:カテゴリ/:観点` | 前の観点ランキング。カテゴリの「何が気になる？」へつなぐ（音質など並べられない観点はそう書く） |

- 判断：`lib/nakami-model.ts`（中身・ぜんぶの項目・気にしていることを先に・残念が少ない順・乗り換え・くらべる・定型文・検索の解釈・表示名）。テスト `lib/nakami-model.test.ts`（24件。docs/11 の実データの数字も固定）
- 画面：`src/app/`（部品・板・枠・覚えること・画面遷移）と `src/pages/`（4画面）。`src/styles/app.css` 1つ
- 観点の日常語：`lib/category-definitions.ts` に `word`（装着感 → つけ心地）。抽出に渡す `label` は変えていない
- 外したもの：四象限・観点ランキング・前のくらべる・前のホームと商品ページ（`src/compare` など）、使わなくなった `lib/compare-model.ts`

### 確かめたこと

- テスト 132件すべて通る。型の検査も通る。`npm run build` も通る（JS 236KB・gzip 44KB。データを含む）
- 実際のブラウザで、スマホ幅（390px）8画面・PC 幅（1440px）2画面：横のはみ出し・11px 未満の文字・44px 未満の押せる所が無いこと、画面のエラーが無いこと
- 操作の流れ23項目：行を押すと板が開く（URL に ?k=）→「気になる」で案内 → Esc で閉じる → 気にしていることが上に出る → 乗り換えると同じ板のまま次の商品 → 戻るで前の商品の板 → もう一度戻ると板が閉じる → くらべるに2つ入れると札 → くらべる画面 → カテゴリは気にしていることで開く → 観点を押すと並びが変わる → 予算の外は薄く → 名前・楽天の URL で探せる → 前の URL がつながる
